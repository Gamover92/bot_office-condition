# 2026-11-11: убрать авто-пересоздание виджета

## Намерение и почему

Бот раз в 60 секунд (фоновый цикл `widget.run_widget_updates`) пересоздаёт
виджет-сводку: шлёт новое сообщение и удаляет старое, чтобы обновить запечённый
в HTML график. Пользователю не нравится, что бот сам трогает чат: любые новые
сообщения от бота без запроса воспринимаются как спам и дёргают переписку.

## Цели / анти-цели

- Цель: в чате не появляется новых сообщений от бота без действия пользователя.
- Цель: значения метрик продолжают обновляться вживую (public_data раз в 5 с,
  правка существующего сообщения, без новых сообщений).
- Анти-цель: не ломать ручное обновление кнопкой «Обновить» и выдачу по `/climate`.
- Принятое ограничение: график в виджете замораживается на момент отправки и
  обновляется только по «Обновить» / повторному `/climate`.

## Подходы

1. **Только ручное «Обновить» (выбрано)** — убрать ветку авто-пересоздания из
   цикла; оставить живые правки public_data. Кнопка «Обновить» уже пересоздаёт
   виджет со свежим графиком (`handlers/climate.py:on_button`) — поведение
   знакомое пользователю, ноль новых сообщений от бота.
2. Редкое пересоздание (15–30 мин) — отвергнуто: бот всё равно периодически
   шлёт сообщения, чего пользователь не хочет.

## Изменения

- `app/widget.py`: из `update_widget_data_once` убрать ветку пересоздания
  (кулдаун `HTML_REFRESH_SEC`, отправка нового виджета + удаление старого).
  Кэш прохода упрощается до `(data, n)`. Удаляются `_last_seen`,
  `note_chat_message`, константа `HTML_REFRESH_SEC` — они обслуживали только
  авто-пересоздание.
- `app/handlers/climate.py`: убрать catch-all `track_last` (больше не нужен).
